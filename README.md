# YOUTH CLUB SEOUL — Upcoming Events

서울유스클럽 모임·이벤트 보드. GitHub Pages로 발행하는 정적 사이트다.

| 파일 | 하는 일 |
|---|---|
| `index.html` | 공개 페이지. 보기 + 참석 신청만 가능하다. |
| `data/events.json` | 이벤트 원본. 이 파일이 유일한 출처다. |
| `data/config.json` | 신청 접수 주소(`signupEndpoint`). 배포 후 여기만 채우면 신청 폼이 켜진다. |
| `apps-script/Code.gs` | 신청 접수 백엔드. 구글 스프레드시트에 붙여 웹 앱으로 배포한다. |
| `yclb-index.html` | YCLB Index(회원명부). 데이터는 없고, 본인 확인을 마친 사람에게만 Apps Script가 명부를 준다. |
| `posters/` | 이벤트 포스터 이미지. |
| `assets/` | 로고, 나눔바른고딕 서브셋(SIL OFL). |

## 왜 이런 구조인가

정적 사이트에는 서버가 없다. 방문자가 남긴 **휴대폰 번호를 저장소에 넣으면 공개 웹에
그대로 놓이므로**, 접수는 저장소 바깥에서 받아야 한다. 그 역할을 Apps Script와
스프레드시트가 맡는다.

```
방문자 ──[이름·뒷자리 4]──▶ Apps Script ──▶ 스프레드시트 (뒷자리는 여기까지만)
                            │
   공개 페이지 ◀──[이름·순번만]──┘
```

정원 판정도 서버가 한다. 브라우저에서 세면 우회할 수 있지만, 접수 시점에 시트가
순번을 매기므로 실제 선착순이 보장된다.

## 접수 백엔드 배포

1. 구글 드라이브에서 **새 스프레드시트** 생성 (이름 자유).
2. 확장 프로그램 → **Apps Script** → 기본 코드를 지우고 `apps-script/Code.gs` 붙여넣기.
3. **배포 → 새 배포 → 유형 `웹 앱`**
   - 설명: 아무거나
   - **실행: 나**
   - **액세스 권한: 모든 사용자**
4. 배포 → 권한 승인(본인 계정) → 끝에 `/exec` 로 끝나는 **웹 앱 URL** 복사.
5. 왼쪽 ⚙️ **프로젝트 설정 → 스크립트 속성 → 속성 추가**: 이름 `ADMIN_KEY`, 값은 긴 임의 문자열.
   관리자 화면 [토큰] 창의 '신청자 조회 키'에도 같은 값을 넣는다. **코드에는 적지 않는다** — 이 저장소는 공개다.
6. `data/config.json` 의 `signupEndpoint` 에 그 URL을 넣고 커밋.

그 순간부터 각 이벤트 카드 하단에 이름·휴대폰 뒷자리·카톡 닉네임 입력칸과 [참석 신청] 버튼이 나타난다.

> 코드를 고치면 **배포 → 배포 관리 → 편집 → 버전 '새 버전' → 배포**를 해야 반영된다.
> 그냥 저장만 하면 기존 URL은 옛 코드를 계속 쓴다.

### 신청자 보기

전체 번호는 받지 않는다. **휴대폰 뒷자리 4자리**만 받아 동명이인을 가리고,
YCLB Index 인증도 `이름 + 뒷자리`로 맞춘다. 명부에는 전체 번호든 뒷자리만이든 둘 다 된다.


- 가장 확실한 방법은 스프레드시트를 직접 여는 것이다. `signups` 탭에 접수순으로 쌓인다.
- 화면에서 보려면 `?action=phones&key=<ADMIN_KEY>` 로 요청한다. `ADMIN_KEY` 는
  스크립트 속성에 있고, 비어 있으면 이 조회는 닫힌다. 공개 응답에는 뒷자리·닉네임이 실리지 않는다.

### 취소 처리

시트의 **취소** 열에 아무 값이나 적으면 그 신청은 명단에서 빠지고, 뒤 순번이 한 칸씩
당겨진다. 대기자가 자동으로 확정으로 올라간다.

## 이벤트 데이터

`data/events.json` 의 `events` 배열. `title` 과 `date` 만 필수다.

```json
{
  "id": "premium-lunch-grand-hyatt",
  "title": "프리미엄 런치: 그랜드 하얏트",
  "host": "김지훈",
  "capacity": 4,
  "capacityText": "4인",
  "date": "2026-09-20",
  "time": "12pm",
  "place": "그랜드 하얏트 1F 더 테라스 키친",
  "placeUrl": "https://naver.me/...",
  "address": "서울 용산구 ...",
  "fee": "205,000원",
  "note": "줄바꿈으로 여러 줄 가능",
  "image": "posters/grand-hyatt.jpg",
  "kind": "event",
  "orgs": ["Google", "Amazon", "Apple"],
  "attendees": ["직차", "성보"],
  "formUrl": "https://forms.gle/...",
  "links": [{ "label": "강남역 거점방", "url": "https://invite.kakao.com/tc/..." }],
  "status": "auto"
}
```

- `kind` 가 `"event"` 면 대형 이벤트로 본다 — 참석자 이름 대신 `orgs` 를 알파벳순
  상자로 보여주고, 좌석 눈금과 대기 판정을 하지 않는다. 비우면 소모임(기본)이다.
- `orgs` 는 참석 소속 목록. 관리자 화면에서 쉼표로 적으면 된다.
- `formUrl` 을 채우면 그 구글폼으로 보낸다. 비우면 페이지 안의 신청 폼을 쓴다.
- 요일은 `date` 에서 자동으로 계산한다. `time` 에는 시간만 적는다.
- `attendees` 는 카톡에서 받아 적은 사람들이다. 웹 신청자는 그 **뒤에** 순서대로 붙는다.
- `capacity` 를 채우면 좌석 눈금이 생기고, 다 차면 이후 신청은 **대기**로 넘어간다.
- `status` 를 `auto` 로 두면 정원 상태를 보고 배지가 알아서 바뀐다.
- `image` 는 `posters/…` 상대 경로, 또는 `https://` 주소.

## 포스터

인스타그램 세로 게시글과 같은 **3:4**로 잘라 보여준다. 카드에서는 썸네일, 카드를 누르면
큰 이미지와 내용이 좌우로 열린다. 원본 비율이 3:4가 아니어도 되지만, 3:4로 맞춰 올리면
잘리는 부분 없이 그대로 보인다.

## 검색 노출

`noindex` 와 `robots.txt` 로 막아두었다. 주소를 아는 사람만 본다. 저장소는 공개이므로
**여기에 올리는 것은 모두 공개된다고 보아야 한다** — 휴대폰 번호가 저장소에 들어가서는
안 되는 이유다.

## 글꼴

한글은 나눔바른고딕(SIL OFL 1.1), 라틴·숫자는 Helvetica. 서브셋에서 라틴 글리프를 뺐기
때문에 영문과 숫자는 자동으로 Helvetica가 맡는다.

## YCLB Index (회원명부)

`yclb-index.html` 에는 회원 데이터가 없다. 신청 접수와 같은 Apps Script가 본인 확인을 한
사람에게만 명부를 돌려준다. 이 저장소가 공개라서 데이터를 저장소에 넣지 않는 것이 핵심이다.

```
방문자 ──[이름·뒷자리 4·이메일]──▶ Apps Script ──▶ Index 신청서 응답 시트와 대조
                                       │
   명부 화면 ◀──[공개 항목만, 7일 토큰]──┘   (이메일·휴대폰·거주지는 절대 안 나감)
```

- **열람 조건**: Index 신청서의 이름 + 휴대폰 뒷자리 + 이메일이 모두 맞고, 두 동의 문항에 동의한 사람.
- **표시**: Index 신청자는 실명·체크마크·상세 카드. 그 외 가입자는 `김** / 소속 / 산업`.
  휴대폰 번호가 같으면 같은 사람으로 보고, Index 신청자는 가입 명단 쪽에서 뺀다.
- **무차별 대입 방지**: 같은 이름 5회 실패 시 15분, 전체 60회/10분, 관리자 비밀번호 5회 실패 시 15분 잠김.

### 설정 (한 번)

1. 접수용 스프레드시트의 Apps Script에 최신 `apps-script/Code.gs` 를 붙여넣는다.
2. ⚙️ 프로젝트 설정 → 스크립트 속성:
   - `INDEX_SHEET_ID` — Index 신청서 **응답 시트**의 ID (주소 `/d/` 와 `/edit` 사이)
   - `MEMBERS_SHEET_ID` — 가입 신청서 응답 시트의 ID
   - `INDEX_ADMIN_KEY` — 명부 관리자 비밀번호 (호스트 체크용). 길수록 안전하다.
   - `INDEX_SECRET` 은 비워 둔다. 처음 실행 때 자동으로 생긴다. 바꾸면 모두 다시 로그인해야 한다.
3. **배포 → 배포 관리 → 연필 → 버전 '새 버전' → 배포.** 주소는 그대로라 `data/config.json` 은 안 바꾼다.
   처음 실행 때 다른 스프레드시트를 여는 권한을 한 번 승인해야 한다.

### 운영

- **호스트 경험**: 명부 화면 하단 [관리자] → 비밀번호 → 카드의 '호스트' 체크. 접수용 시트의 `index_hosts` 탭에 쌓인다.
- **소속 표시**: 접수용 시트의 `org_map` 탭. 가입 신청서의 '소속' 원문을 화면에 보일 소속과 산업으로 바꾼다.
  처음 보는 소속은 '표시 소속'이 빈 채로 자동 추가되고, **채울 때까지 화면에 나오지 않는다**
  (소속 칸에 실명을 같이 적는 사람이 있다). 빈 칸을 채우면 2분 안에 반영된다.
- Index 신청서나 가입 신청서에 응답이 들어오면 2분 안에 명부에 반영된다.
- 이벤트 페이지의 인증 딱지도 `INDEX_SHEET_ID` 가 있으면 Index 신청자를 함께 본다.
